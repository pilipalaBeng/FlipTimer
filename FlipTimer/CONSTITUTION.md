## 第 0 条 效力与修改

**C-0.1** 本文件高于单次需求，也高于任何 Agent 的默认习惯。

**C-0.2** 分工：策划案管「产品要什么」，本宪法管「代码怎么实现」。两者冲突时，产品行为听策划案，实现纪律听本宪法。

**C-0.3** 修改任一条款必须同时做三件事：说明理由、更新附录 B 修订记录、同步更新 `test/constitution-check.js`。只改文档不改校验脚本，视为没改。

**C-0.4** 条款编号格式 `C-章-款`。代码注释、提交信息、评审意见可直接引用（例如「违反 C-6.4」）。

**C-0.5** 标注 **（已定 yyyy-mm-dd）** 的条款是用户拍板的决定，Agent 不得自行推翻。要推翻必须先问。

**C-0.6** 本文件与 `test/constitution-check.js` 必须同时存在。只有文档没有自检脚本，宪法就是标语；只有脚本没有文档，规则就没人读得懂。

## 第一章 平台边界（不可逾越的事实）

**C-1.1** 小程序没有后台常驻、没有本地通知、没有系统闹钟接口。任何「退出 / 锁屏后仍能提醒」的需求，直接判定不可实现，不做变通。

**C-1.2** 不做声音，不做震动。要响铃只能写系统日历，不属于本项目范围。

**C-1.3** 前台常亮是产品成立的前提。每次 `onShow` 必须重设 `wx.setKeepScreenOn`。

**C-1.4** 不申请长期订阅消息（工具类拿不到资质，别浪费时间去试）。

**C-1.5** 不做后台计时。切后台只允许「按时间戳重算」，不允许「继续跑」。

**C-1.6 提醒态不设自动超时（已定 2026-10-20）**。没被关闭就一直提醒，**没有任何自动消退路径**。

- 退出 `alert` 只允许经过用户动作：翻转（`handleFlip`）、整屏点击（`onStageTap`）、长按（`onMainLongPress`）、悬浮钮的「关闭」（`onCloseTap`）。
- **禁止**用 `setTimeout` / 计数到点 / 「重进页面自愈」之类的方式结束提醒。手机摆在桌上就是为了"到点能看见"，提醒自己没了，这台钟就是坏的。
- 光能亮多久由 C-7.16 兜住：动画被系统禁用也必须还看得见。

**C-1.7** 产品定位：**这首先是一台时钟，计时只是它附带的功能（已定 2026-10-20）**。中间区任何时候都显示当前时刻，不显示倒计时。任何把这个关系倒过来——让倒计时占据主视觉——的设计，一律不做。

> 违反本章的任何改动，即使功能看起来能用，也必须回退。产品边界不是技术债，是前提。

## 第二章 状态机（唯一真相源）

**C-2.1** 合法状态只有四个：`idle` / `running` / `alert` / `closed`。禁止新增第五个。

**C-2.2** 状态迁移只允许经过这些方法：`handleAction` / `beginRound` / `enterAlert` / `closeAlert` / `cancelRound` / `showClosed` / `toIdle` / `restoreRound` / `syncOnResume`。禁止在事件回调里直接 `setData({ state })`。

**C-2.3** 关闭提醒后一律回 `idle`，**禁止自动开始下一轮（已定 2026-10-20）**。下一轮必须由用户再次翻转或点击触发。

**C-2.4** 计时态（`running`）翻转不响应，避免语义混淆。

**C-2.5** `closed` 必须有兜底收敛：`onHide` 会清掉 1.5 秒定时器，`syncOnResume` 里必须能把它推到 `idle`，否则会永久卡在「已关闭提醒」。

**C-2.6** 每个状态都必须有明确的状态反馈：中间大字或底部小字，至少之一。二者表达同一件事时只留一处，禁止重复。`closed` 态由中间大字承担，底部留空。

**C-2.7 计时态必须能主动取消（已定 2026-10-20）**。没有取消入口的计时器是半成品：番茄钟被打断、临时要出门，用户只能等它响。

- 入口是**长按中央区**，不是长按按钮、不是翻转。翻转在计时态不响应（C-2.4），这条不能为了取消功能破例。
- `cancelRound` 必须**废弃 `targetTs` + 清本轮记录**，且**不得进入 `alert`**——用户是主动结束，不是被提醒。
- 取消后仍走 `closed` 反馈（「已取消本轮」），1.5 秒回 `idle`，**不自动开始下一轮**（同 C-2.3）。
- 取消与关闭共用 `showClosed`，两者只在文案上不同，禁止复制出第二套反馈逻辑。

**C-2.8 面板开着时，翻转只收面板（已定 2026-10-20）**。设置面板打开意味着手正在屏幕上操作，这一下翻转更可能是误触而不是"我要开始一轮"。

- `applyTurn()` 里 `showPanel` 为真时**只调 `onClosePanel()`，不进入任何状态迁移**：不开计时、不关提醒。
- 顺序排在 `alert` 判断之前：面板能在提醒态打开，两条规则同时成立时先收面板。
- 不许"顺手把这一下记下来、收完面板再补执行"——用户收回面板后想开始，再翻一次就是了，替他做决定只会变成误启动。

## 第三章 时间

**C-3.1** 只存目标时间戳。剩余时间永远由 `targetTs - Date.now()` 现算。

**C-3.2** 禁止累加式计时（`elapsed += ...`、`remain--` 之类）。定时器不是时间源。

**C-3.3** 定时器只负责重绘（`TICK_MS = 200`），不承载业务时间。

**C-3.4** 中间区显示格式只由剩余时间决定：常规 `HH:mm`；剩余 ≤ 60 秒改为 `HH:mm:ss`。切换依据是剩余时间，不是分钟边界，避免在 59.9 秒处提前或滞后。

- **带秒必须同时满足两个条件：剩余 ≤ 60 秒，且状态是 `running`。** 到点进入 `alert` 的同一刻就要收回 `HH:mm`——那一串秒是"快到点了"的提示，到点即失效，留着它只会让人以为还在倒计时。
- **这道门槛写在 `renderClock()` 内部，不靠调用方自觉。** 传参给"是否带秒"，只要有一处漏判状态，秒就会赖在屏幕上不走；写在取时入口里，误传也拦得住。

**C-3.5** 最后一分钟显示的是**当前时刻的秒**，不是剩余秒。中间区任何时候都不得出现倒计时数字**（已定 2026-10-20）**。

**C-3.6** 显示文字每次都必须从 `new Date()` 现取，不得缓存或推算。时钟走时与小程序的计时器状态无关，`idle` 和 `running` 用同一套取时逻辑。

**C-3.7** `targetTs` 的**赋值**只允许发生在 `utils/countdown.js` 内部（通过 `start()` / `resume()`）。页面只能读取，不得自己维护第二份时间。

## 第四章 传感器与降级

**C-4.1 主判据用陀螺仪，加速度计只作降级（已定 2026-10-20，推倒重来）**。`wx.onDeviceOrientationChange` 已废弃，禁止使用。

这条改过一次，原因写在这里免得下次又被"简化"回去：

> 加速度计读的是**重力在设备坐标系里的方向**。手机平放在桌上、在桌面平面内转 180°，屏幕朝向变了，重力方向一点没变 —— 前后两帧的读数完全相同。所以只要手机是平放的，加速度计就**永远**不知道你翻了。
> 上一版把加速度计当唯一判据，真机表现是"翻十次中一次、只在一个方向像是有效"，靠的是转动时手抖出来的那点倾斜。不是阈值没调准，是传感器选错了。

绕屏幕法线旋转，唯一有明确读数的是**陀螺仪 z 轴角速度**。所以 `FlipDetector` 优先 `wx.startGyroscope` + `wx.onGyroscopeChange`，起不来才退回加速度计那套点积判据。

**主判据是三根轴都认的（1.21 补）**。陀螺仪给的是设备角速度向量的三个分量，**不许只取 z**：竖翻绕屏幕法线、读数在 z；横翻（绕屏幕纵轴转半圈，屏幕由朝自己变成朝外）读数全在 y。只认 z 的后果是真机反馈的"竖翻好了，横翻没反应"——用户不该记哪个方向翻才算翻。具体怎么选轴见 C-4.2。

**降级路径的模长下限不许写绝对值（已定 2026-10-20）**。微信文档里加速度单位一会儿写 g（静止约 1）一会儿写 m/s²（约 9.8），差 9.8 倍。写死 `mag < 0.35` 这种阈值等于赌其中一种口径，赌错这条防御就形同虚设，而且仿真和真机可能一边一个答案。所以判据是**跟自身量级比**：`magRef` 用指数平滑跟着读数走（首帧直接取），低于它的 35% 才算"正在被甩动、读数不可信"。

**C-4.2 翻转判据是角速度积分，认当前主导轴（1.21 修，不再是"只认 z 轴"）**。常量各管一件事，缺一个都会坏：

- `OMEGA_DEAD = 0.35`（rad/s）死区。静止零偏远低于此值，正常转动至少高一个量级。没有死区，零偏会慢慢积分成假翻转。
- `TURN_RAD = 150°`。剩下 30° 交给惯性，不要求转满整圈。
- `SPIN_HOLD_MS = 8000`。静止这么久才丢弃累积量，好让"转 90° 停一下再转 90°"能累积成一次。
- `MAX_DT_MS = 250`。**单帧积分上限**。采样周期 60ms，掉三四帧仍按真实间隔积分。上限不是越小越安全：钳到 120ms 时，一次 200ms 一帧的快速翻转只算得到六成弧度，转满 180° 也认不出来——**翻了不认比误触发更难查**，用户只会觉得这东西时灵时不灵。
- `STALL_MS = 1000`。**断流判定**。间隔超过一秒说明中间被挂起、被弹窗挡住或掉帧掉狠了，那段空隙里手转没转无从得知，积分它等于凭空造角度——丢掉这一帧，只把时间基准接上。它和 `MAX_DT_MS` 是两件事：一个管"这一帧算多久"，一个管"这帧还算不算数"，不许合并成一个常量。
- 秒级间隔（挂起再回来可能是几十秒）靠 `STALL_MS` 挡掉，这也是 `MAX_DT_MS` 能放宽到 250 的前提。
- `AXIS_SWITCH_RATIO = 1.5`。**换轴门槛**。当前轴的读数还在发力时不许被别的轴顶掉，否则一次竖翻会被手腕的横向歪动打断，用户的感觉就是"翻一半没反应"。新轴要明显压过当前轴（1.5 倍）才切。

**选轴的三条规矩，少一条都会坏**：

1. **三轴里谁在转就积谁**（取绝对值最大的那根）。只认 z 轴：横翻完全不响应。
2. **换轴时必须把已攒的角度作废**（`spin = 0`）。两根轴的积分拼在一起就是个假角度——横翻转 100°、再换竖翻转 100°，两根轴各贡献 100°，凑出来的 200° 从来没有在物理上发生过。
3. **换轴要防抖**（`AXIS_SWITCH_RATIO`）。见上面那个常量。

**死区判断放在选轴之前**：三轴都在 `OMEGA_DEAD` 以下时保持当前轴不动，不要去"猜"哪根轴最大 —— 静止时三轴读数都是零偏噪声，谁大谁小纯属随机，跟着它换轴会把分段累积（转 90° 停一下再转 90°）打散。

**`dt` 必须除以 1000 换成秒**：角速度单位是 rad/s，直接拿毫秒相乘会把结果放大一千倍，屏幕上任何微小抖动都够触发一次翻转。这个 bug 写过一次，仿真当场抓到（`43/53` 全红）。

**C-4.3 两个方向一视同仁；姿态与动作分两条路走（已定 2026-10-20，第二次重写）**。

这条被推翻过两回，两次都为了同一件事：**别让用户觉得"翻一下没反应"**。

- 第一版是 `armed` 单向记账——"待机态必须 `armed` 为真才启动"。它解决的问题是真的（关掉提醒后把手机翻回原位，不该又开起来），但任何一次未被消耗的翻转都会吃掉武装，用户感受到的就是"有时候翻一下没反应，得再翻一次"。
- 第二版换成 3 秒时间冷却，问题没解决反而更糟：冷却叠在 1.5 秒反馈期后面，反馈期结束后还要再挡 1.5 秒，屏幕上已经回到待机了，翻一下还是没反应。

现在的规则：

- **判据里对 `Math.abs(this.spin)` 取绝对值**，正转反转是同一条式子，不存在"只认一个方向"。
- **动作走队列，不在传感器回调里执行**。`_commitTurn()` 只做两件事，**顺序不能换**：先 `pending++`（记账，纯数值不可能失败），再 `_setPose()`（渲染，要碰 `setData`）。页面在 `onTick` 里 `takeTurns()` 取走执行。真机上"内容转过来了、计时没起来"就是渲染和动作挤在同一个回调栈里、渲染那步出岔子把动作一起带走的后果——回调栈里的异常只进 console，页面上什么也看不见。
- **被锁挡下时不清零累计角度**：`_commitTurn()` 返回 false（`lockUntil` 未到）时留着 `spin`，下一帧接着试。清零再返回等于把用户已经转过的 150° 直接扔掉。
- **防误启动只靠 `showClosed` 的 1.5 秒反馈期**，不叠加任何时间冷却。反馈期内 `state === 'closed'`，翻转本来就进不来；反馈期一过就是待机，翻一下必须立刻启动。

**一次翻转兑现后（`spinDone`）必须把剩下的角度丢掉，再给 1.2 秒兜底复位**。手把 180° 转完的总角度可能到 190°，多出来的部分若不丢弃，下一次反方向翻转就要多转十几度才触发，来回几次就明显变钝。兜底复位是防"手一直在轻微动、角速度始终在死区上方"把后续翻转全吞掉。

**C-4.4** 姿态上报与动作派发解耦：翻转必然改姿态（`pending++` 之后调 `_setPose`），至于要不要启动 / 关闭，由页面按当前状态裁决（`applyTurn`）。**禁止把两者写回同一个同步调用链**——那就是 C-4.3 里那个真机故障。

- **姿态现在只在 `FlipDetector` 里记账**（`this.upsideDown`）。1.20 版起它不再驱动界面旋转：系统自己会转页面（C-7.11），页面收到姿态变化只重算悬浮钮位置。
- **翻转的开关链路是产品的骨架，任何显示层的改动都不许碰它**：`_commitTurn()` → `pending++` → 页面 `onTick` 里 `takeTurns()` → `consumeTurn()` → `applyTurn()` → `beginRound()` / `closeAlert()`。删掉"内容转 180°"这类显示补偿时，**这条链一个字都不能少** —— 用户翻手机就是为了开和关，不是为了让画面转。
- 姿态变化即使什么也不做（将来可能连悬浮钮都不用重算），`_setPose` 的幂等保护也要留着：它是"姿态与动作各走各的"这条边界的落点。

**C-4.5** `onShow` 必须启动传感器，`onHide` 必须停止。禁止让传感器在后台空跑。`_handleGyro` / `_handleAccel` 开头必须检查 `this.running` —— 停止之后可能还有一帧在回调路上，不挡会继续积分。

**C-4.6** 传感器不可用时必须有纯点击 / 按钮的完整备用路径，且状态小字改为「点击开始」。

**C-4.7** 传感器启动**不得**套 `wx.requirePrivacyAuthorize`。加速度计 / 陀螺仪不在微信隐私接口名单里，套上之后一旦小程序隐私保护指引没生效（本项目长期处于审核中），这个接口直接 `fail`，会把传感器一起拖死，翻转整个失灵——2026-10-20 真机就是这个原因（已定 2026-10-20）。传感器启动失败只走 C-4.6 的静默降级，不弹任何授权框。

**C-4.8** 采样频率用 `'ui'`（60ms），不用 `'game'`（20ms）。省电优先。**两条启动路径各写一次 `interval`，检查必须分别查两处** —— 只查一处会漏掉另一处，变异测试就是靠这个暴露的。

**C-4.9 传感器"假可用"必须能判出来；启停必须处理迟到的 success（已定 2026-10-20）**。这两个都不是"能不能翻"的问题，是"翻不动了还不说"的问题。

- **假可用**：接口调用成功、`running` 为真，却**一帧都不送**。它不算启动失败，走不到 C-4.6 的降级，页面会一直写着「翻转开始」，用户翻到手酸也没反应，还不知道可以改用按钮。`utils/flip.js` 必须有 `pollSilent()`：连续 `SILENT_MS`（3 秒）没有新帧即判定不可用，由页面在滴答里轮询并走降级。判定自带 1 秒节奏，页面不必自己记拍。
- **启停竞态**：`wx.startGyroscope` / `wx.startAccelerometer` 的 `success` 是**异步**的。点进页面立刻切后台时，`stop()` 若因为 `running` 还是 false 就什么都不做，迟到的 success 会把传感器起在后台（违反 C-4.5）；而它同时把 `running` 置真，下一次 `start()` 又被挡住不再重启 —— 翻转从此失灵，且不掉降级路径。启停必须带**意图标志** `wantRun`：迟到的 success 只负责把自己关掉，不注册回调、不置 `running`。
- 累计角的超时清零必须放在死区判断**之外**：手持续微动时角速度常年高于死区，只在"停下来"那一刻才判超时就永远清不掉，攒几次抖动会攒出一次假翻转。

## 第五章 存储

**C-5.1** 所有存储 key 以 `flip_timer_` 开头。

**C-5.2** 只存**无法重算**的最小信息：本轮目标时间戳、用户设定时长。禁止存剩余秒数、进度、状态名。

**C-5.3** 每处写入必须有确定的清理时机，且清理点写在附近注释里。

**C-5.4** `closeAlert` 必须**即刻**清除本轮记录，不等 1.5 秒反馈期。否则反馈期内进程被杀，重进会重复弹提醒。

**C-5.5** 读存储必须做值域校验，非法值一律回落到默认值。

## 第七章 视觉与样式

**C-7.1** 背景纯黑 `#000000`。

**C-7.2** 尺寸单位一律用 `vh` / `vw`，禁止用 px 写死字号（1px 边框例外）。

**C-7.3** 数字必须等宽（`tabular-nums`），避免秒跳动时整行抖动。

**C-7.4** **不做像素偏移防烧屏（已定 2026-10-20）**。1px 相对字号是伪防护，量级上不成立。禁止复活 `drift` 机制。

**C-7.5 呼吸光是「从屏幕物理边缘向内侧的 alpha 渐变」，不是贴边一圈亮线（重写 2026-10-20，二版）**。只在 `alert` 态出现，单一颜色，周期 4～6 秒。

光分两段实现，各自职责固定：

- **样式串由 `utils/prefs.js` 的 `glowStyles()` 拼好，绑在节点的 `style` 属性上；`styles/glow.wxss` 里只留几何和动画。** 这不是风格偏好，是被 WXSS 编译器逼出来的：`rgba(var(--gc), var(--a1))` 这种写法会在编译期被整条丢掉，不报错、控制台干净，真机上表现为「到点了但一片黑」。详见 C-7.15 的红线。
- **近场 = `box-shadow`**：只负责贴边最亮那一圈，3 层足够。堆层数没有意义——它们都在同一小段距离内衰减，多出来的层只是重复描同一段边。**禁止 `spread`**：它会先扩出一段实心区再模糊，亮带内沿必是断崖，观感像贴了一圈荧光胶带。**禁止 `border-radius`**：铺满全屏后圆角会在四角画出弧线亮边。
- **远场 = `.glow-far` 的四条渐变带**：`box-shadow` 的高斯衰减在 30vh 之外已经掉到肉眼看不见（alpha < 0.05），**半径再拉长也只是"更长的看不见"，带宽做不出来**。必须另用四条 `linear-gradient` 把中远处的 alpha 抬起来。
- 每条渐变用 `background-size` 限制**自己的带宽（当前 24%）**，在这条带里从 0.14 完整走完到 0。**禁止在渐变里写中途 stop 百分比**（如 `0.14 0%, 0 34%`）——中途归零会造成层与层之间的折线，屏幕上能直接看到一条直边。带宽由 `background-size` 控制，不由 stop 控制。
- **禁止纯 `box-shadow` 六层方案**：实测四角因双方向叠加而发亮、边中点发暗，形成 X 形不均匀，且带宽始终不够。
- 四边带宽用相同百分比（横屏长边是短边的 2.17 倍，同百分比换算成像素后左右自然更长，视觉才均衡）。这条与"物理等深"结论相反——**观感优先**：物理等深会让左右只剩 13% 的视觉带宽，看着像只有上下在发光。
- 中间区必须保持纯黑。渐变带在 24% 处归零，中心不叠任何颜色；**禁止用全屏单层渐变**，那会把时钟数字的对比度一起吃掉。
- 谷底 `opacity: 0.3`，不更低：落到 0.2 时边缘 alpha 只剩 0.076，一个 5 秒周期里大半时间"看起来没在提醒"。

**C-7.6** 禁止红绿蓝循环、禁止高频闪烁、禁止全屏闪白。

**C-7.7** 禁止 emoji、禁止渐变色卡片、禁止圆角大卡片堆叠。**渐变只允许出现在 `prefs.glowStyles()` 生成的远场串里**（C-7.5 的远场），`wxss` / `wxml` 里一个字都不许有，也不得出现在面板、按钮、卡片背景上——"AI 三件套"禁的是装饰性渐变，不是功能性的光。

**C-7.8** 全黑界面必须保留极淡的状态点或状态小字，避免看起来像关机。

**C-7.9** `HH:mm:ss` 比 `HH:mm` 多两个冒号段，字符从 5 个涨到 8 个。切换时字号必须同步缩小（当前 42vh → 30vh）并带 `font-size` 过渡；缩放后两种格式占屏宽比例应接近，禁止缩到看不清来换取不溢出，也禁止溢出裁切。

**C-7.10 可点击元素必须撑够触摸高度（已定 2026-10-20）**。横屏时 `vh` 是**短边**，手机短边只有 390～430px，`1.2vh` 的内边距换算下来不到 5px，点击区不足 20px，手指根本戳不中。

- 可点击元素的类里必须有 `min-height`，当前基准 **7vh**（约 27px）。
- 禁止用加大 `padding` 或加大字号来凑高度——那会把视觉一起放大，破坏「不抢主视觉」的前提。
- 待机态唯一的设置入口（时长按钮）不得暗到看不见：颜色比正文暗一档即止，不许再用 `#5f5a52` 这种近乎隐形的值。

**C-7.11 贴胶囊的 UI 放在内容层之外；内容不许做 180° 主动补偿（2026-10-20 第二次修订）**。微信系统胶囊（`···` / `×`）是原生层，横屏下也压在右上角，页面盖不住也挤不开它。

- 悬浮钮（`.fab`）放在 `.flipper` **外面**。它只跟着页面坐标系走，不跟着姿态走。
- **红线：内容层里不许出现 `rotate(180deg)` 之类的姿态补偿。** 这个坑踩了两轮：

  > 1.15 版为了查「画面在转、计时不起来」，加过自检面板和一个 ROT 开关，就是怀疑"画面本来就是系统在转"。1.20 版真机给了答案：**页面固定横屏（`pageOrientation: "landscape"`），手机立在桌面上翻 180° 时重力向量整体反号，系统会自己把页面转 180°** —— 内容本来就是正立的。而 `.flipper` 又主动转了一次，两次叠加，用户看到**字是倒的**。
  > 1.19 版顺着"系统不转"的错误假设，还给悬浮钮加了镜像（翻过去后挪到物理左下角）。系统既然转了页面，桌面右上角在页面坐标里仍是右上角，镜像反而把钮送到对角。1.20 一并撤掉。

- **姿态只在 `FlipDetector` 里记账**，页面收到姿态变化（`applyPose`）只做一件事：重算悬浮钮位置。翻过去之后胶囊在页面坐标系里换了个角，`onLoad` 算一次是不够的。
- 位置一律由 `wx.getMenuButtonBoundingClientRect()` + 窗口尺寸换算（`utils/fab-pos.js`），**禁止写死 `top` / `right`**：异形屏、分屏、不同机型上胶囊位置会漂，写死迟早撞进去。
- 拿不到胶囊矩形、或拿到的坐标系不对时回落到固定 `13vh / 3vw`。两种情况都算不对：横屏拿到竖屏坐标（`right` 会跑到屏幕外），以及**系统把页面转过去之后胶囊落到下半屏**（它已不在页面右上角了）。
- `.fab` 必须有 `z-index` 压过铺满全屏的 `.main`，否则点击被它吃掉。
- 四角仍然只留给**不承担点击**的文字（`提醒时间 HH:mm`、状态小字）。除此之外，不许再有第二个贴角控件。
- 这条的成立前提是 `pageOrientation` 固定横屏。**若将来改成 `auto` 或改为平放姿态使用，系统旋转的前提就没了，补偿要不要加回来必须重新用真机确认，不许照抄结论。**

**C-7.12 悬浮钮分两级：细棍常驻，菜单按需（已定 2026-10-20）**。全黑界面上常驻一排按钮，等于每轮都埋一次误触陷阱。

- 收起态只有一根细棍（`7vh × 0.8vh`），看得出、不抢眼。
- 点击区靠 `min-width: 11vh` + `min-height: 8vh` 撑开（C-7.10），视觉仍是细棍本身，不许把细棍放大来凑点击区。
- 展开态从右上角长出纵向菜单（图标 + 文字），`transform-origin: top right`，收起时有 180~220ms 过渡。
- 收起态的菜单必须 `visibility: hidden` **且** `pointer-events: none`：只靠 `opacity: 0` 的话，透明菜单还挂在那儿等着被误触。

**C-7.13 菜单会自己缩回，点空白优先收起（已定 2026-10-20）**。参照小米悬浮球的交互习惯。

- 展开后 **3 秒**无操作自动收起（`utils/fab.js` 的 `FAB_HOLD_MS`）。这份状态机独立于页面，因为页面已经装了状态机 + 计时 + 持久化，再塞一套定时器会混成一团。
- 点任意菜单项：**先收起再执行**。菜单不许在执行后留在屏幕上挡事。
- 菜单展开时点屏幕空白处：**只收起，不触发任何动作**。顺序写反了就会出现「想收菜单，结果把计时开了」。
- `onHide` 必须清掉收起定时器，否则切后台回来会莫名其妙缩一下。

**C-7.14 提醒态不换中间的字，时钟继续走（已定 2026-10-20）**。到点之后，屏幕上唯一的变化是边缘的光。

- 中间**继续显示当前时间**，禁止换成「起来走走」这类文案。换字等于把时钟从屏幕上拿走，直接违反 C-1.7。
- 提醒态**必须继续走时**：`onTick` 要把 `alert` 纳入刷新范围。到点的光可能亮很久（C-1.6 不设超时），数字若冻在到点那一分，用户想看一眼几点了，还得先把提醒关掉——这是把提醒变成了时钟的前置条件。
- 因此禁止复活 `.alert-title` 之类的提醒标题样式。
- 提醒的"存在感"全部由 C-7.5 的边缘光承担；底部 `翻转或点击关闭` 是唯一的文字提示，不重复。

**C-7.15 发光样式只走预置档，且必须输出完整 rgba 字符串（重写 2026-10-20，三版）**。允许用户改颜色和强度，但样式值必须由 JS 拼成成品，不许交给样式表自己算。

- **红线：任何地方都不许出现 `rgba(var(--x))` / `rgb(var(--x))`。** WXSS 编译期会逐个校验 `rgba()` 的参数，撞上 `var()` 这种非数值就把**整条声明丢掉**——不报错、控制台干净、代码看着完全正确，真机上就是「到点了但屏幕一片黑」。本项目 2026-10-20 真机首测就是栽在这上面。颜色和 alpha 由 `glowStyles()` 拼成 `rgba(94, 214, 160, 0.38)` 这样的完整字符串，绑到 `style` 属性（运行时字符串，WebView 直接解析，不过编译期校验）。
- 颜色只给**三个预置**（绿 / 红 / 蓝），取值统一压低饱和度。纯 `#FF0000` 在全黑屏上像报警灯，边缘光要的是"余光扫到能注意到"，不是"扎眼"。禁止做取色器自由选色。
- 强度是**倍率**（淡 0.72 / 标准 1 / 浓 1.3），不是让用户直接填 alpha。直接暴露 `0.38` 这种数值对用户没有意义，而且能调到把中间的时间冲掉。
- **三色 × 三档只算一次**：`glowStyles()` 按 `rgb + 倍率` 即时拼串，不许写九份重复的 `box-shadow` 和渐变。
- 非法配色 id **回落到显式默认值**，不是"列表第一项"——强度列表第一项是「淡」，用 `list[0]` 兜底会让"存储被写坏"和"首次进入"落到不同档位。
- 面板里必须有**实时预览条**：待机态屏幕本来不发光，用户改完看不见效果等于盲选。预览条用同一份样式串和呼吸动画，不留双重实现。

**C-7.16 提醒光不许只靠动画表达存在（已定 2026-10-20）**。`.glow-on` 必须同时给出**静态 `opacity: 1`** 和 `animation`，两者不是二选一。

- 呼吸是 `animation` 改 `opacity`，而 `.glow` 的基准值是 `0`。**动画一旦不跑，opacity 就停在 0**：iOS「减弱动态效果」、低电量模式、WebView 回收合成层、部分机型省电策略，任何一个都会让动画不动。
- 后果和 C-7.15 那个坑外观完全一样——**到点了，屏幕一片黑**，而且更难查：代码没错、编译没错，只是动画被系统掐掉了。
- 给了静态 `1` 之后：动画正常时照旧呼吸；动画被掐掉时静态全亮。**"光在"这件事不能依赖动画。**
- 同理，**呼吸谷底不许低于 `0.3`**（C-7.5），"弱"可以，"没有"不行。

## 第十一章 禁止清单

**C-11.1** 下列写法禁止出现在本项目代码里：

| 禁止 | 原因 |
|---|---|
| 用 `setInterval` 累加剩余时间 | 掉帧、切后台会产生累计误差 |
| 用屏幕方向 API 判断物理翻转 | 已废弃，且拿不到倒置状态 |
| 翻转判定只看某根轴 | 拿起手机换轴会导致漏检 |
| 待机态不看 `armed` 就触发启动 | 归还姿态那一下会误启动下一轮 |
| 用 `armed` 挡住提醒态的关闭 | 用户得翻两次才关得掉，会以为没反应 |
| 提醒态自动消失 | 违反「提醒须被确认关闭」 |
| 1px 像素偏移防烧屏 | 量级不成立，是伪防护 |
| 在 `pages/` 里写通用工具函数 | 破坏单向依赖 |
| 引入 npm 包 | 包体积与审核成本上升 |
